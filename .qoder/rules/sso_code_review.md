# IAM Platform项目代码审查、测试与文档规范

## 1. 代码审查规范

### 1.1 审查重点

- **功能正确性：** 是否满足需求
- **代码质量：** 是否符合编码规范
- **安全性：** 是否存在安全漏洞（特别是 OIDC/OAuth2 相关逻辑）
- **性能：** 是否存在性能问题
- **可维护性：** 是否易于理解和维护

### 1.2 审查清单

- 代码是否符合项目结构规范
- 是否包含必要的注释和文档
- 是否遵循命名和编码规范
- 是否处理了异常情况
- 是否包含单元测试
- 是否存在安全漏洞
- 是否考虑了性能影响
- OIDC/OAuth2 端点是否按标准协议实现
- JWT 签名和加密是否正确
- 用户密码是否使用 BCrypt 加密
- Client Secret 是否在响应中妥善保护（仅创建时返回一次）

## 2. 测试规范

### 2.1 测试分类

- **单元测试：** 测试单个方法或类
- **集成测试：** 测试多个组件的协作（使用 Testcontainers 提供 PostgreSQL 和 Redis）
- **端到端测试：** 测试完整的 OIDC 流程（Authorization Code + PKCE）
- **性能测试：** 测试系统性能指标（Token 签发/验证延迟）

### 2.2 测试覆盖率要求

| 测试类型 | 覆盖率要求 |
|----------|-----------|
| 核心业务逻辑 | 100% |
| 重要功能 | 90%+ |
| 一般功能 | 80%+ |
| 边缘功能 | 70%+ |

### 2.3 测试命名规范

- 测试类命名：`{被测类名}Test`，如 `UserApplicationServiceTest`
- 测试方法命名：`should{行为}When{条件}`，如 `shouldCreateUserWhenValidRequest`
- 集成测试类后缀：`IT`，如 `UserApplicationServiceIT`

## 3. 文档规范

### 3.1 文档类型

- **API文档：** 使用 Swagger/OpenAPI 规范（Springdoc）
- **技术文档：** 系统设计、架构说明
- **用户文档：** 使用手册、操作指南
- **运维文档：** 部署说明、监控配置

### 3.2 文档更新要求

- 需求变更时更新需求文档
- 代码变更时更新相关文档
- 架构调整时更新架构文档
- 定期审查和更新过时文档

### 3.3 API 文档注解

- 所有 REST Controller 必须使用 `@Tag` 注解
- 所有接口方法必须使用 `@Operation` 注解
- 请求/响应 DTO 字段使用 `@Schema` 注解
- OAuth2 客户端创建响应中 clientSecret 字段标注敏感信息
